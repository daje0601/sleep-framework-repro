# ARC Sleep v3, seed 42

This experiment targets the 80% success rate reported for Sleep in Table 4. The starting weights are the pinned Llama-3.2-1B-Instruct snapshot. Seed 42 starts at the first of the 11 registered training tasks. The previous H100 checkpoint belongs to v2. The v3 evaluation loader requires a training checkpoint with the same protocol fingerprint, matching settings and the full episode count. [Sleep Table 4 and Appendix B.3](https://arxiv.org/html/2606.03979v2#A2.SS3) · [Experiment configuration](../configs/arc_sleep_v3.json)

**Equation (4).** Compute Levenshtein distance on the generated token IDs of the complete student and teacher dreams, including their shared teacher prefix. For distance at most `z₀`, use one minus the distance divided by the longer dream length. Return zero above that threshold. Two empty dreams receive one. The ARC appendix supplies no numeric threshold. We fixed **z₀ = 1 token** before evaluation, the smallest cutoff allowing partial credit for one edit. An actual terminal control token is omitted from dream content. [Sleep §3.3](https://arxiv.org/html/2606.03979v2#S3.SS3) · [Reward and loss](../src/sleep_repro/objectives.py)

**Knowledge Seeding.** A frozen teacher generates the reference. Sample a uniform proper token prefix of a nonempty reference, or the empty prefix for an empty reference. The student completes it within the same total response budget. The final displayed KS objective places both terms on student outputs. Both terms therefore use the same sampled continuation after this prefix. The frozen semantic judge compares the complete decoded dreams. The edit reward operates on their original token IDs. Each contributes half of the reward. [Sleep §3.3](https://arxiv.org/html/2606.03979v2#S3.SS3) · [Training path](../src/sleep_repro/engine.py)

The minimized loss is the conditional forward KL weighted by α, minus the detached reward times the sampled continuation’s log probability weighted by (1−α). We use α = 0.5. The KL averages per-token divergences within each continuation, following the GKD definition, and the sequence log probability sums the action log probabilities. Both terms average over student continuations. Rollouts and their loss use the full categorical distribution at temperature 0.8. Only the actual student actions are scored, including a sampled stop token if one occurred. These temperature and prefix conventions are registered implementation choices. [GKD Eq. (2)](https://arxiv.org/pdf/2306.13649) · [Sampling regression test](../tests/test_ks_v3.py)

**Directive and evaluation.** The directive prompt shows visible input/output demonstrations and requests one JSON object describing training settings. It lists the permitted fields and ranges. The experiment makes 60 generation attempts per training task and ranks valid directives as in v2. The evaluation denominator is eight fixed tasks × five independent attempts. A format error counts as a failed attempt. Every test input in a task must match its single predicted grid for the attempt to succeed. The primary result will report successes out of 40, tasks solved at least once out of eight, and the percentage-point difference from 80%. A match at 32/40 establishes a numeric match for this seed and scoring procedure. The authors’ exact task IDs, answer-candidate allowance and handling of malformed directives remain unverified. [ARC comparison](PAPER_AUDIT_KO.md) · [Prompt regression test](../tests/test_prompt_v3.py)

**Cloud execution.** Each H100 stage uses the same v3 source commit and experiment configuration. The one-task GPU preflight records wake and consolidation time, one directive generation, fixture adaptation and one grid prediction to estimate the subsequent jobs against available credit. Training starts from the base checkpoint and writes a checkpoint after each episode. After verifying all 11 episodes and successful termination, evaluation uses the final checkpoint, including when the total number of accepted policy updates is zero. Each stage has a finite time limit, persistent artifacts and a terminal job and billing check. [VESSL instructions](VESSL.md)
